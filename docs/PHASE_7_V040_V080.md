## Phase 7.1 — Critical Security Hardening (v0.4.0)

### Changes
- Refresh token now blacklisted on logout — subsequent `/refresh` calls with a revoked token return 401
- `/refresh` endpoint validates against the token blacklist before issuing a new access token
- Rate limits extended: `/refresh` (10/min), `/predict` (30/min), `/analysis/score` (10/min)
- Swagger UI, ReDoc, and OpenAPI JSON schema disabled in production (`APP_ENV=production`)
- HSTS (`Strict-Transport-Security`) header added for production responses
- TOCTOU race condition in first-user admin promotion fixed using `pg_advisory_xact_lock`
- `source_type` field on dataset upload validated as a `Literal` enum (rejects arbitrary strings)
- Uploaded filenames sanitized before storage (strips path separators and special characters)
- Missing `db.commit()` in `delete_dataset` endpoint corrected (deletes were silently not persisted)
- Raw exception messages stripped from API error responses — clients receive generic structured errors

### Files Modified
- `backend/app/api/auth.py` — blacklist check on `/refresh`, rate limit decorators
- `backend/app/api/data.py` — source_type Literal validation, filename sanitization, db.commit() fix
- `backend/app/api/predict.py` — rate limit on `/predict`
- `backend/app/api/analysis.py` — rate limit on `/analysis/score`
- `backend/app/main.py` — conditional OpenAPI schema registration, HSTS header
- `backend/app/services/users.py` — pg_advisory_xact_lock for first-user promotion
- `frontend/src/stores/auth.js` — logout() sends refresh_token to server

### Verification
- [x] Logging out invalidates refresh token; `/refresh` returns 401 on subsequent call
- [x] `/docs`, `/redoc`, `/openapi.json` return 404 in production
- [x] HSTS header present on production responses
- [x] Rapid concurrent first-registration requests result in exactly one admin
- [x] Upload with path-traversal filename is sanitized
- [x] API errors return `{"detail": "..."}` — no stack traces

## Phase 7.2 — New Endpoints & Feature Completeness (v0.5.0)

### Changes
- **GET /admin/users** — paginated user listing (skip/limit params)
- **GET /analysis/runs** — lists past analysis scoring runs for the current user
- **GET /admin/stats** — platform usage statistics (user count, dataset count, prediction count, model count)
- Concurrent training job guard: starting a second training job while one is running returns HTTP 409
- `preview_dataset` limit parameter bounded (`ge=1, le=1000`) to prevent oversized responses
- `ListingItem` schema: `asking_price ≥ 0`, `size_m2 ≥ 1` validation constraints added
- `stored_path` removed from `DatasetFileResponse` (internal path no longer exposed to clients)
- `LoginRequest.password` `max_length=128` added (prevents bcrypt DoS via long password)
- In-process model cache: trained model objects cached in memory, eliminating per-request joblib reads
- Old refresh token blacklisted on rotation (not only on logout)

## Phase 7.4 — Performance Improvements (v0.7.0)

### Changes
- Model cache invalidated after a new training job completes — predictions always use the latest model without a restart
- Redis caching added to GET /stats/trend (joins expensive aggregation across multiple years)
- Database index on `dataset_files.uploaded_at` — speeds up ORDER BY clauses on dataset listings
- Database index on `training_jobs.status` — speeds up WHERE status IN (...) queries used by job polling
- `UniqueConstraint` on `region_lookup` prevents duplicate region records on repeated RPE/RN imports

### Files Modified
- `backend/app/services/ml.py` — cache invalidation hook on training completion
- `backend/app/api/stats.py` — Redis cache decorator on `/stats/trend`
- `backend/alembic/versions/` — migration: indexes on dataset_files.uploaded_at, training_jobs.status
- `backend/app/models/region.py` — UniqueConstraint on region_lookup

### Verification
- [x] First prediction after training uses the newly trained model (cache miss + reload)
- [x] Second prediction hits in-process cache
- [x] `/stats/trend` response headers show cache hit on second request
- [x] Duplicate RPE/RN import raises IntegrityError and is handled gracefully
